# Lessons

Patterns learned from corrections. One line each: what went wrong, the rule that prevents it. Review at session start; not part of the default reads in `AGENTS.md`.

- `tests/run.mjs` filters suites by substring: `trip-unit` also runs `sharedtrip-unit`. Fine for safety, but expect more suites than named.
- A standing "commit and deploy each phase" permission (memory) does not carry over to unrelated tasks; for tooling work the owner asked for explicit approval.
- Very long shell commands with a heredoc (many lines, quotes) failed with "unexpected EOF" and wrote nothing: write files with the Write tool and keep shell commands short.
- Several source files have mixed CRLF and LF endings. A scripted replace of a multi-line string silently did nothing on CRLF text: convert CRLF to LF before replacing and restore afterwards (a small node script), and grep to confirm the change landed.
- In a timing-sensitive browser suite (`live`, pin-moves check) add new checks after the existing timing checks, never in the middle: a check inserted earlier shifted the timing and failed only under the parallel runner. Run the suite alone and grouped (`node tests/run.mjs live party friends`) before trusting it.
- A new What's new entry pushes the oldest of the three shown entries out; update the `dashboard` suite's "announced" assertion in the same change (or append to the newest entry).
- The Supabase CLI asks for `--yes` on hosted `db push` and `functions deploy` in agent runs; use it only under the owner's standing phase-deploy choice, and dry-run first.
- A browser mock that runs the real handler (`handleManual`) or real SQL (PGlite) behind the HTTP route finds more than hand-written fake replies; reuse the pattern in `tests/progression.mjs`, `sessions.mjs`, `steam.mjs`.
- Never read `localStorage` or `indexedDB` in a default parameter or at module load: when site data is blocked the property getter throws before any try/catch (the `prefs` suite's blocked-storage check caught it). Reach them inside the try.
- In a browser test that imports a module the page also loads, import the URL the page actually fetched (`performance.getEntriesByType('resource')`): after an edit Vite serves it with `?t=`, a second copy of the module with its own state.
- Snapping a font size up on a crowded row (the panel tabs, 12.5 to 13 px in the type-scale change) can push the last button out of its container; the narrow-layout check lives in `tests/shell.mjs`, which a targeted run of "the typography suites" missed. After a size, padding or font change run the full browser set once, not only the suites that mention the changed screens.
- A screenshot comparison is only as good as its determinism: focus and text selection in an autofocused field differed with machine load (one screen in 258). Blur and clear the selection before a capture, and confirm a "difference" is real by re-capturing single-job against the old CSS (`git show <rev>:src/styles.css` into the working tree, then restore).
- Use `scripts/ui-baseline.mjs --compare A B` for a visual change: it writes a report of only the screens that differ, with the changed regions boxed. Run it before and after, in both themes and on the five viewports (`DESIGN.md` section 13).
- A touch-target `::after{position:absolute}` needs a positioned parent: add every control that gets one to the `position:relative` list in the `pointer:coarse` block of `styles.css`, or the pseudo-element grows to the nearest positioned ancestor and covers its neighbours on touch screens only. Test touch UI with real touch events and `elementsFromPoint`, not `.click()` (`tests/tripstouch.mjs`).
- Leaflet ignores `setView` with a zoom change while a zoom animation runs (`_animatingZoom`), and in a headless browser that animation can last over 600 ms. Code that moves the map on every selection must wait for `zoomend` and let only the latest request run; tests must wait for a condition (marker spacing, position), not a fixed pause (`sessions-map-explorer.js`, `tests/sessions-explorer.mjs`).
- Measure "the marker is in the middle" from the marker's screen rectangle, not `map.getCenter()`: the dock hides part of the map and a turned map (`maprotate.js` turns the pane about the container centre) shifts what a centre means.
- A closed (suspended) `<dialog>` keeps its DOM: on sign-out, empty it, or private text stays on the page behind the map. `reset()` in `sessions-hub.js` now does.
- A gesture test that starts at the centre of a block element can land under a neighbour's `::after` touch target (touch hit-testing snaps to it) once the block gets wider. Start inside the text, away from the bar buttons (`tests/popswipe.mjs`).
- `git stash pop` on Windows (autocrlf) can turn LF files into CRLF in the working tree: a scripted edit must read, normalise to LF, replace, and restore the file's own line ending, then grep to confirm the change landed.
- `classList.add` of a class the element already has still fires a MutationObserver (attribute `class`). An observer that re-applies a class to what it watches loops forever: check `contains` first (More tools redrew its rows hundreds of times a second until guarded).
- Folding a Leaflet control into a menu: keep the control and press it from the row (`a.click()`), hide its bar with a class, and move focus to the visible trigger before a dialog opens, so the dialog's "return focus to the opener" lands on something visible (`map-more-tools.js`).
- Unit `contrast` requires every `:hover` rule inside `@media (hover:hover)`, so a "selected and not hovered" style cannot use `:not(:hover)`: put the selected rule before the hover rule so hover wins by order.
- Moving an action behind a collapsed `<details>` (Help topics) breaks tests that click it: open the topics first (`document.querySelectorAll('.dash-topic').forEach(d => d.open = true)`), or the click times out as "not visible".

- Browser tests with fixtures dated around "today" go red when the calendar day rolls over (`trips`, `sidedrag` failed from 2026-11-15: a trip ending 14 Nov became a past trip). Pin the page clock in the test (`ctx.clock.install` + `resume`) instead of moving every date. Check a red suite against the unmodified file before blaming the change.

- Never publish from git-ignored generated data without comparing it to what is live (2026-11-15: a stale `public/data` removed five China regions). `npm run deploy` now restores and preflights against gh-pages.

## 2026-11-15 (Flight Sessions Discover and auto-attendance)
- **Redefining a function that several migrations already redefined: start from the newest definition, not the first.** `purge_user_sessions` gained the report delete in the moderation migration; copying the series migration's body would have silently dropped it (`db-sessions-v2-moderation-unit` caught it). Grep `create or replace function public.<name>` across all migrations and diff the bodies before copying.
- **The app on :5173 may be `vite preview` of `dist/`, not `npm run dev`.** Browser suites then test the last build: run `npm run build` (with `VITE_SUPABASE_*` from `.env.development.local` in the shell, or the account UI is absent) before them. `diag` imports `/src/log.js` and only works against the dev server.
- **A new mocked setof RPC must be added to `SETOF` in the session browser suites**, or the mock returns a scalar and the screen silently shows an empty list.
- **A DOM fixture failure after a markup change is expected**: regenerate `tests/fixtures/html-dom-baseline.json` (source digest and elements) in the same commit, after checking that only the intended elements were added.
- Class names: `.ses-person` already belongs to the manager's people panel; the attendee list uses `.ses-attendee`.

## 2026-11-15 (one-click guest, session XP explanation)
- **Before a browser run, check what owns :5173.** Vite moves to 5175 when 5173 is taken, and the suites still hit 5173: a leftover `vite preview` of an old build answered, and the splash and sessions checks failed on code that was not under test. Run `npx vite --port 5173 --strictPort` (fails loudly instead) and confirm the served file has your change (`curl localhost:5173/src/<file>`).
- **A figure shown to people must come from the database settings it describes.** The host reward amounts (`host_base_xp`, `host_per_attendee_xp`) were not readable by the app; a read-only `session_xp_rates()` supplies them, and the browser test changes the settings to prove the text follows.
- Scripted edits of source that contains regex or template literals, run through a shell heredoc, get their backslashes mangled (word boundaries and newlines turn into control characters): use the Edit tool for those and a node script only for plain strings.
- A transport close fails every pending command: if the command layer reports each as an acknowledgement failure, two of them fault the session with the wrong reason before the real "transport lost" event arrives (found in the Phase 3 stop-validation scenario). Report the loss once, from the close event.
- A persisted safety flag must change in the state machine only after the side effect reports success: the machine marked the recovery marker cleared before the controller tried to delete it, so a failed delete left the workflow unlocked. Make such effects request/result event pairs (`MARKER_CLEAR_RESULT`), and test with a storage fixture whose `removeItem` fails and one where it silently does nothing.
- One state serving two physical situations (USB-only and powered stop validation) hid a missing safety flow behind a handoff instruction. Give each physical situation its own flow and entry guard, and make the handoff procedure match what the machine enforces.
- In a browser suite that runs a flow ending in a deliberate fault with a persisted recovery marker, start the next scenario in a fresh browser context: the marker correctly sends the reloaded page to recovery (`tests/bench-lab.mjs`).

## 2026-11-17 (live MSP/DShot analysis)
- A `node -e` edit written inside a bash string can miss silently (a replace that matches nothing is not an error): after every scripted edit, grep for the expected result, or use the Edit tool. One missed call (`initAircraftDiagnostics`) only showed up in the browser test.
- A test command started as `( a; b ) &` inside a background task dies with the task but can leave its Vite server running, and the next run fails with "Port in use". Start the test command itself with `run_in_background`, and check the lab ports (5188, 5189, 5190) before a rerun.
- `innerText` applies CSS `text-transform`: a kicker styled uppercase reads "ACTIVE SWEEP". Use `textContent` for exact strings in browser suites.
- Collect analysis samples before the tick's own output decision, and expect a first sample at command 1000 (before any output was sent); assertions on commanded values must allow it.
- The static wording test also rejects "faulty motor" (and "diagnosis") in any bench string; the one sentence that states what a result does NOT mean is exempt by exact match in `tests/bench-safety-unit.mjs`.
- When a machine ends a sweep at the same instant telemetry goes stale, the collector never sees the gap: record the stale stretch from the last frame when the sweep ends.

## 2026-11-19 (aircraft electronics profile, combined confirmation)
- Editing `src/` or its CSS while a browser suite runs against a Vite dev server hot-reloads the page under test and shows up as a state timeout (`fourway-ui` waited 60 s for `POST_SCAN_RESTORE`). Do not edit source while a suite runs; rerun the suite alone when it happened.
- A multi-line node patch script pasted into a shell heredoc failed to parse (unmatched quote) twice: write the script with the Write tool and run it with node. Scripted `replace` of a string that appears nowhere throws only because the helper checks; keep that check.
- A nested section inside the result card must not reuse the `.eyebrow` class: browser suites select `#bt-sec-result .eyebrow` and hit a strict-mode violation. Nested blocks use an `h3.dg-block-title`.
- A "difference observed" peer result can be only a start-threshold difference (the synthetic aircraft has four different start values): eligibility for the combined run blocks on RPM or DShot differences, not on that.
- The static wording test rejects "guarantee" and "diagnosed" in any bench string and "reflash" (the word "bootloader") outside `esc-ui.js`, `electronics.js` and `electronics-ui.js`.
