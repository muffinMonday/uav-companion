# Lessons

Patterns learned from corrections. One line each: what went wrong, the rule that prevents it. Review at session start; not part of the default reads in `AGENTS.md`.

- `tests/run.mjs` filters suites by substring: `trip-unit` also runs `sharedtrip-unit`. Fine for safety, but expect more suites than named.
- A standing "commit and deploy each phase" permission (memory) does not carry over to unrelated tasks; for tooling work the owner asked for explicit approval.
- Very long shell commands with a heredoc (many lines, quotes) failed with "unexpected EOF" and wrote nothing: write files with the Write tool and keep shell commands short.
- Several source files have mixed CRLF and LF endings. A scripted replace of a multi-line string silently did nothing on CRLF text: convert CRLF to LF before replacing and restore afterwards (a small node script), and grep to confirm the change landed.
- In a timing-sensitive browser suite (`live`, pin-moves check) add new checks after the existing timing checks, never in the middle: a check inserted earlier shifted the timing and failed only under the parallel runner. Run the suite alone and grouped (`node tests/run.mjs live party friends`) before trusting it.
- A new What's new entry pushes the oldest of the three shown entries out; update the `dashboard` suite's "announced" assertion in the same change (or append to the newest entry).
- The Supabase CLI asks for `--yes` on hosted `db push` and `functions deploy` in agent runs; use it only under the owner's standing phase-deploy choice, and dry-run first.
- A browser mock that runs the real handler (`handleManual`) or real SQL (PGlite) behind the HTTP route finds more than hand-written fake replies; reuse the pattern in `tests/progression.mjs`, `sessions.mjs`, `steam.mjs`.
- Never read `localStorage` or `indexedDB` in a default parameter or at module load: when site data is blocked the property getter throws before any try/catch (the `prefs` suite's blocked-storage check caught it). Reach them inside the try.
- In a browser test that imports a module the page also loads, import the URL the page actually fetched (`performance.getEntriesByType('resource')`): after an edit Vite serves it with `?t=`, a second copy of the module with its own state.
- Snapping a font size up on a crowded row (the panel tabs, 12.5 to 13 px in the type-scale change) can push the last button out of its container; the narrow-layout check lives in `tests/shell.mjs`, which a targeted run of "the typography suites" missed. After a size, padding or font change run the full browser set once, not only the suites that mention the changed screens.
- A screenshot comparison is only as good as its determinism: focus and text selection in an autofocused field differed with machine load (one screen in 258). Blur and clear the selection before a capture, and confirm a "difference" is real by re-capturing single-job against the old CSS (`git show <rev>:src/styles.css` into the working tree, then restore).
- Use `scripts/ui-baseline.mjs --compare A B` for a visual change: it writes a report of only the screens that differ, with the changed regions boxed. Run it before and after, in both themes and on the five viewports (`DESIGN.md` section 13).
- A touch-target `::after{position:absolute}` needs a positioned parent: add every control that gets one to the `position:relative` list in the `pointer:coarse` block of `styles.css`, or the pseudo-element grows to the nearest positioned ancestor and covers its neighbours on touch screens only. Test touch UI with real touch events and `elementsFromPoint`, not `.click()` (`tests/tripstouch.mjs`).
