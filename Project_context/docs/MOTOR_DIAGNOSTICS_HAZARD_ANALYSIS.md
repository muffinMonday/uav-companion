**Conventions:** "Stop" means external value 1000 plus the four-part stop proof (repeated 1000, FC read-back of 1000 for every enabled motor, valid RPM zero for the observation period, user confirmation that no motor is rotating). All timings are provisional. Tests marked *mock* run on a mocked transport; tests marked *HW* need supervised hardware and are unverified today.

## Addendum 2026-11-17: ESC identification (4-way)
New hazards for the read-only 4-way scan; evidence and tests in `MOTOR_DIAGNOSTICS_FOURWAY_IDENTIFICATION.md`. H13 the flight controller stays in 4-way mode (no firmware timeout): fail closed with the battery instruction, no transport claim. H14 ESCs left in the bootloader or motor outputs left off after exit (Betaflight 2025.12.5 by source reading): no fresh zero-RPM telemetry, restoration proof fails, fault. H15 a motor or MSP byte written while the FC parses 4-way: hard gates in the controller, motor boundary and state machine; no stop is claimed while in 4-way. H16 a mutating 4-way command: allowlist at encode time, static tests. H17 a different board answers after the scan: identity re-read fault. The scan is not enabled for real hardware until the owner's supervised check.

## Not covered by software

Physical hazards that software cannot remove: the battery plug is the only guaranteed emergency action; an operator who ignores on-screen instructions; mechanical failure of a motor on a bench; ESC or battery thermal events. These stay in the instructions shown before testing and in the final report.
