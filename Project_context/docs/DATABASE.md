# Data storage

Three layers: (1) static files built at build time, (2) per-browser `localStorage`, (3) optional Supabase Postgres for signed-in users. Verified against `src/` and `supabase/migrations/` on 2026-11-12. Migrations are the source of truth for layer 3.

## 1. Supabase (Postgres, `public` schema; `supabase/migrations/`, applied in order)
**Access model:** RLS on every table. The only policy is `user_data_select_own` (select, `authenticated`, `user_id = auth.uid()`). `anon` and `authenticated` have all table privileges revoked (select on `user_data` granted back). All writes and all other reads are `security definer` functions (`set search_path = ''`) that read `auth.uid()`, reject anonymous callers, and never return another user's id (people are named by friendship, member or trip ids). Execute is revoked from `anon` on every function. No triggers of our own; no cron (cleanup happens inside functions). `20261111121000_harden_api_exposure.sql` revokes API access to the platform's `rls_auto_enable()`.

| Table | Key and columns | Constraints and notes |
|---|---|---|
| `user_data` | PK `user_id` to `auth.users` (cascade); `doc jsonb`, `rev bigint`, `updated_at`, `device` (<= 80), `markers`, `trips` | `rev >= 1`; doc is an object, <= 2 MB. One personal cloud copy per user |
| `user_data_versions` | PK `(user_id, rev)`; doc, counts, device | No policy (functions only). Kept 30 days, at most 20; a save within 2 minutes of the same device's last one keeps no version (`20261115110000_version_coalesce.sql`), a forced overwrite always does |
| `profiles` | PK `user_id`; `display_name` (1 to 40), `friend_code` unique (10 hex), `accepts_requests`, `last_seen`, `show_online`, `avatar` (key of `profile_avatars()`), `bio` (1 to 160), `location` (1 to 60, typed text), `interests` (up to 5 keys of `profile_interests()`), `share_profile`, `named` (false until a name is chosen; set by `choose_name`, a name given or a rename) | Functions only |
| `friendships` | `id`; `requester`, `addressee` to `auth.users`; `status` pending or accepted; `responded_at` | `requester <> addressee`; unique index on the unordered pair; indexes on both sides |
| `blocks` | `id`; `blocker`, `blocked`; unique pair | Blocking ends the friendship; the blocked person is not told |
| `shared_trips` | PK `id` (the client's trip id); `owner`; `doc` (`{v, trip, items}`), `rev`, `members_rev`, `name` (1 to 80), `markers`, `updated_by` | Doc <= 1 MB, <= 500 markers; index on `owner` |
| `shared_trip_versions` | PK `(trip_id, rev)` | Cascade from trip; 30 days, at most 20; a save within 2 minutes of the same person's last one keeps no version |
| `trip_members` | `id`; `trip_id`, `user_id`; `role` owner or editor; `status` invited or joined; `invited_by` | Unique `(trip_id, user_id)`; index on `user_id` |
| `friend_live_locations` | PK `user_id`; `lat`, `lon`, `accuracy`, `device`, `updated_at` | The latest position of a person sharing with their friends (migration `20261117100000`); no policies, functions only; deleted by `stop_sharing_friends`, `stop_all_sharing`, `delete_profile`, account deletion (cascade) |
| `live_locations` | PK `(trip_id, user_id)`; `lat`, `lon`, `accuracy`, `updated_at`, `device` (nullable, 1-64 chars) | Range checks; latest position only; one device holds it (migration `20261112100000_live_device.sql`) |

Flight Sessions 2.0 (migration `20261118100000`; RLS on, no table privileges): `flight_sessions` adds `visibility` (private|public), `latitude`/`longitude` (both or neither; required for public), `timezone`, `capacity`, `publication` (published|unpublished), `unpublished_*`; `location` is the label. `session_removals` (session, user), `session_notices` (user, session, kind, title snapshot, read_at; purged after 60 days). Guests may call only `list_public_sessions` and `get_public_session` (safe fields, no ids of people). Rules: five active hosted sessions per host, same-host overlap within 300 m blocked, 10 creations per 24 h, capacity checked under the session row lock. Attendance XP: `can_verify_session`.

Flight Sessions 2.0, later migrations: `flight_session_series`, `session_invitations` (named or via link; scope occurrence or series), `session_links` (token stored only as sha256; shown once), `session_reports`; `flight_sessions` adds `series_id`, `series_ordinal`, `overridden`. Guests: only `list_public_sessions`, `get_public_session`. Public sessions are off while `progression_settings.public_sessions_enabled` = 0. Details: `supabase/README.md`.

Progression tables (all RLS on, no table privileges; details in `PROGRESSION.md` and `supabase/README.md`): `progression_ranks` (tier, key, name, min_xp, rising), `progression_settings` (key, value: `sim_xp_per_hour` 10, `attendance_xp` 50, `steam_manual_cooldown_minutes` 60, `steam_enabled` 0), `app_roles` (user, admin or organiser), `xp_ledger` (append-only; unique `(user_id, source, ref)`; `amount`, `source` sim, attendance or admin, `reason`, `actor`, `meta`), `user_xp` (`total >= 0`, `peak_tier`; kept by trigger), `achievements` (definitions: category, rarity, icon, metric, threshold, optional season window), `user_achievements` (permanent), `featured_achievements` (position 1 to 3, only unlocked), `user_counters`, `flight_sessions`, `session_rsvps`, `session_attendance` (verified_by, verified_at, revoked_at), `steam_apps` (approved App IDs), `steam_links` (Steam id, counters, `state_steam_id` = the Steam account the stored totals belong to; kept after unlinking), `steam_app_state` (last total per game; kept after unlinking so relinking the same account credits only new play), `steam_credited` (Steam id, game, highest total ever counted; never deleted, so a Steam account's history pays out once).

**Functions (callable by `authenticated` only; the helpers `clean_display_name`, `check_trip_doc` and `is_party_member` by nobody)**
- Cloud copy document: `{ v: 1, items, trips, settings? }`. `settings` is optional and additive (no version bump, no migration; `save_user_data` passes unknown keys): `{ theme: system|light|dark, themeAt: ms }`, present only once the user has chosen a theme. Last writer wins by `themeAt` (`mergeSettings` in `sync/core.js`); it is not part of the content comparison, so it never causes the both-sides-changed question. The adapter reads it with `select(settings:doc->settings)`. Old clients rebuild the document without it; a newer client puts it back at its next check.
- Cloud copy: `save_user_data(p_doc, p_base_rev, p_device, p_force)` returns `ok` or `conflict` with the server's revision; `list_user_data_versions`, `restore_user_data_version`, `delete_user_data`.
- Deletion: `delete_profile` (profile, friendships, blocks the caller made, live positions, places in shared trips, and the progression: XP ledger and total, achievements, featured, counters, attendance, Steam link and totals; roles stay; the cloud copy stays) and `delete_account` (all of that plus `user_data` and its versions). A trip the caller owns passes to the joined member who joined first (new owner, `members_rev` bumped), or is deleted with its invitations when nobody else joined. Both can be run again. The `auth.users` row is removed by the `delete-account` edge function after `delete_account` succeeds; every table references it with `on delete cascade`, so nothing is left behind. Tests: `tests/db-account-unit.mjs`, `tests/delete-account-unit.mjs`.
- Audit trail (`audit_events`, migration `20261116120000`, applied to the hosted project 2026-11-13): append-only (no delete, no TRUNCATE; the only update is `delete_profile` nulling an `actor` or `subject` that names the person deleted), no foreign keys, `meta` a small object, no free text, no Steam ids. Events: `role.grant`, `role.revoke`, `attendance.revoke` (reason as a code: mistaken_mark, no_show, duplicate, abuse, other), `steam.link`, `steam.unlink`, `steam.status` (changes to private or error only), `setting.change` (trigger on `progression_settings`), `profile.delete` (tombstone with no actor, subject or id); `area.*` reserved. Read only by `admin_audit_events(limit, action)` (administrators; friend codes, not ids). XP adjustments stay in `xp_ledger`. Browser side: the local diagnostic log is IndexedDB `uavzones-log` (one store `log`, up to 500 entries, 200 KB, 7 days) and the `uavzones.v1.debug` flag; neither is synced or sent.
- Friends: `ensure_profile`, `set_accepts_requests`, `regenerate_friend_code`, `request_friend(code)` (one answer for every failure reason; limits 50 pending, 200 friends), `respond_friend`, `remove_friendship`, `list_friends`, `block_user`, `list_blocked`, `unblock`, `delete_profile`.
- Shared trips: `share_trip` (owner, at most 20 per owner), `invite_to_trip` (accepted friends only; at most 10 people), `list_invitable_friends`, `respond_trip_invite`, `leave_trip`, `remove_member`, `delete_shared_trip` (owner-only), `list_my_trips` (reads no document: the dates are the `start_date` / `end_date` columns; `live_active` counts other members sharing their location in the last 2 minutes), `list_trip_members`, `get_shared_trip`, `save_shared_trip(p_trip, p_doc, p_base_rev)` (members; conflict on stale revision), `list_shared_trip_versions`, `restore_shared_trip_version`. `check_trip_doc` refuses Home markers, check-ins and over-limit docs.
- Profile: written only by `update_profile(p_patch jsonb)` (a key present is applied, null clears; the whole patch is refused if any value is bad). `ensure_profile` returns your own. Others see `avatar` always (accepted friends, joined party members, the editor in the version list); `bio`, `location`, `interests` only when `share_profile` is on, and never on a pending request. No function returns an email or a user id. The avatar and interest lists exist in SQL and in `src/avatars.js`; `tests/db-profile-unit.mjs` checks they match.
- Presence: `touch_presence` (writes `last_seen` at most every 15 s), `set_show_online`; status columns in `list_friends` and `list_trip_members` are null unless the viewer is an accepted friend or joined co-member and both show status.
- Friends' live: `share_location_friends(lat, lon, accuracy, device, claim)` (needs an accepted friendship; same 2 s limit, device claim and 10-minute purge as trips; `nofriends` if there is none), `stop_sharing_friends(device)`, `list_friend_live_locations()` (accepted friends only, `member_id` = friendship id, 2-minute window; a friend who is also sharing in a trip with the caller is left out because they are shown as party). `list_my_trips` also returns `online_others` (other joined members seen within 75 s, both sides showing their status).
- Live: `share_location` (joined members; at most one per 2 s; `ended` a day after the trip's `endDate`; deletes rows older than 10 min, only when there are some: indexed on `updated_at`; reads the end date from the `shared_trips.end_date` column), `stop_sharing_location`, `stop_all_sharing`, `list_live_locations`. Each takes an optional device id (`p_device`, a random string the page makes at load); `share_location` also takes `p_claim` (first position after sharing is turned on). The device that claims takes the row over; another device's later send returns `moved` and changes nothing, and its stops delete nothing. No device id = old behaviour (rows under 2 min old, joined members only). `leave_trip` and `remove_member` delete the person's position.

- Progression (all `authenticated`): `get_progression(kind, id)`, `list_progression(kind, ids)`, `my_progression()`, `my_xp_history(before, limit)`, `set_featured(keys)`, `my_roles()`; administrators: `admin_adjust_xp`, `grant_role`, `revoke_role`, `admin_verify_xp`, `revoke_attendance`; sessions: `create_session`, `update_session`, `close_session`, `cancel_session`, `list_sessions`, `rsvp_session`, `withdraw_rsvp`, `list_session_rsvps`, `mark_attended`; Steam: `my_steam`, `unlink_steam`, `list_steam_apps`. Internal, never callable by users: `award_xp`, `rank_for`, `has_role`, `can_manage_session`, `progression_viewable`, `progression_payload`, `user_metric`, `evaluate_achievements`, `bump_counter`. Service role only (edge functions): `steam_link`, `apply_steam_playtime`, `claim_manual_sync`, `release_manual_sync`, `list_steam_due`.

**Ownership:** a user owns their `user_data`, `profiles`, `blocks`; a friendship belongs to both sides; a shared trip belongs to its owner and is editable by joined members, deletable only by the owner. Deleting an `auth.users` row cascades.
**Hosted project:** link in `supabase/.temp/` (git-ignored); the one project doubles as dev. See `supabase/README.md` for tests, pushing and advisor warnings (the "signed-in can execute SECURITY DEFINER" warnings are accepted).

## 3. Files
- **Export/import (GeoJSON, `uavzones: 1`):** Points `[lon, lat]` with `properties` (id, type, name, note, created, optional day/order/date/endDate/unverified/tripId/isSub/parentId/checkin), optional top-level `trips`. Import merges by id; existing ids skipped; markers of unknown trips arrive untagged. Home markers are exported, never put in share links.
- **Share links:** `#import=z.<deflate-raw base64url>` and compact `z2.` (`sharecompact.js`; row slots 11 = Side Quest flag, 12 = parent row number, both absent on main stops, so older links and rows are unchanged); no Home, check-ins, notes, checklists.
- **Static data (`public/data/`, not in git):** `index.json`, `<country>/manifest.json`, hashed PMTiles per region, `places/`. Sources in git: `data/regions/<country>/country.json`, `<region>/source.json` + `boundary.geojson`, `data/places/<country>.txt`. Hubei: 84,863 cells, verified against the shapefile by `npm run verify:data`.

## Migration notes
- The `uavzones.` prefix and `uavzones: 1` flag predate the rename and stay so old data loads.
- Stored days are converted to dates at start-up (see `DECISIONS.md`, day from date).
- A changed stored shape: bump `v`, add a loader for the old one, add a line here. A new SQL change: a new migration file, never edit an applied one; add a `tests/db-*-unit.mjs` check.
